# 发布与运维

本文面向负责打包、分发和现场支持的管理员。开发细节见仓库根目录 `README.md`。

## 1. 版本号

版本号只有一个来源：`campus-src/package.json` 的 `version`。

构建时自动注入到：

- 前端 `__APP_VERSION__` / `__BUILD_TIME__`
- `index.html` 的图标缓存参数 `?v=...`
- exe 文件/产品版本资源
- exe `/health` 与设置 → 诊断
- `campus-edition/version.json`

发版前先改 `package.json`，不要手改 exe 资源或 HTML。

## 2. 配置

### 网页版

`campus-edition/config.json`：

```json
{
  "apiBase": "https://api.deepseek.com",
  "apiKey": "sk-..."
}
```

也支持环境变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_API_BASE`，优先级高于配置文件。

### exe

读取 exe 同目录的 `config.json`，与内置配置合并。外部文件优先；外部文件解析失败时回退到内置配置，并在 `/health` 的 `config.error` 和日志中显示原因。

支持 UTF-8 BOM。以前 BOM 会导致静默回退，现在会明确记录。

### 是否把 Key 嵌进 exe

默认**不嵌入**。只有：

```powershell
$env:CAMPUS_EMBED_KEY = '1'
node build.mjs
```

才会读取 `campus-edition/config.json` 并嵌入。嵌入后任何拿到 exe 的人都能提取 Key，只适用于完全受控、不外借的单机。

## 3. 构建与发布

```powershell
# 只更新网页版
node scripts/release.mjs

# 网页版 + exe
node scripts/release.mjs --exe

# 网页版 + exe + 同步 U 盘
node scripts/release.mjs --exe --usb D:\校园助手
```

脚本会：

1. 在 `campus-src` 执行生产构建。
2. 把 `dist` 同步到 `campus-edition`，写 `version.json`。
3. 可选打包 exe（默认不嵌入 Key）。
4. 可选同步到 U 盘：exe 放根目录，网页版放 `网页版\`。
5. 生成 `campus-exe/release/manifest.json`，含版本、构建时间、exe SHA256、网页版 index 哈希。

U 盘同步不会覆盖目标目录已有的 `config.json`，避免把开发机 Key 带到分发盘。

## 4. 健康检查

```powershell
Invoke-RestMethod http://127.0.0.1:8130/health
```

返回示例：

```json
{
  "app": "campus-assistant",
  "version": "0.2.0",
  "buildTime": "2026-11-21T07:00:08.986Z",
  "pid": 19440,
  "port": 8130,
  "startedAt": "2026-11-21T07:00:14.287Z",
  "uptime": 5,
  "config": {
    "configured": true,
    "source": "file",
    "error": null
  },
  "logDir": "C:\\Users\\young\\AppData\\Local\\CampusAssistant\\logs"
}
```

`config.source` 取值：

- `file`：读取同目录 config.json
- `embedded`：没有外部配置，使用内置配置
- `embedded-fallback`：外部配置解析失败，已回退
- `missing`：网页版没有 config.json
- `file-error`：网页版 config.json 解析失败

## 5. 日志

| 形态 | 路径 |
| --- | --- |
| exe | `%LOCALAPPDATA%\CampusAssistant\logs\server.log` |
| 网页版 | `%LOCALAPPDATA%\CampusAssistant\logs\web.log` |

日志只记录启动、配置来源、端口、代理错误和未处理异常，不记录请求正文、消息内容或 Key。超过 2 MB 会滚动为 `.1`。

## 6. 端口冲突

exe 默认监听 8130：

- 如果 8130 上是**同应用**且 `/health` 可识别，直接打开已有实例，不再启动第二份。
- 如果 8130 被其他程序占用，自动尝试 8131–8139。
- 如果 10 个端口都不可用，写日志并退出。

旧版 exe 没有 `/health`，会被当作“其他程序”，新版会换端口启动，避免打开旧界面。

## 7. 密钥轮换检查清单

如果 Key 曾经出现在 exe、U 盘、备份或聊天记录中，按以下顺序处理：

1. 在 DeepSeek 控制台创建新 Key，确认新 Key 可用。
2. 更新所有运行环境的 `config.json` 或网关配置。
3. 在控制台禁用/删除旧 Key。
4. 检查并清理备份目录中的 `config.json`（本仓库 `_backup/`、`_archive/` 不入库，但本地仍可能存在）。
5. 重新构建并分发 exe；不要继续分发包含旧 Key 的包。
6. 在 `docs/交接文档.md` 记录轮换日期和影响范围。

## 8. 现场排查顺序

1. 浏览器打开 `http://127.0.0.1:8130/health`，确认 `app`、`version`、`config.configured`。
2. 查看 `logDir` 下的日志。
3. 应用内「设置 → 诊断」查看最近错误，导出诊断包。
4. 如果页面白屏，ErrorBoundary 页面可直接导出诊断包。
5. 检查是否有多份 exe/旧实例占用端口；新版会自动识别同应用实例。

## 9. 已知限制

- 未做代码签名，学校环境可能触发 SmartScreen。
- 没有自动更新，U 盘同步仍需管理员执行发布脚本。
- 局域网多机 HTTP 不是安全上下文，摄像头、语音、剪贴板会受限；多机部署应使用 HTTPS 反向代理或校内网关。
- 远端 Files API 附件暂未做引用计数清理。
