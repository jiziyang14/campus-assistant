# 校园助手 · 接手评估与改进路线

> 评估日期：2026-11-21  
> 评估对象：`C:\Users\young\Documents\chat-demo-v0.1.1`（源码）与 `D:\校园助手`（U 盘运行副本）  
> 当前版本：应用 `0.1.2`；exe 资源版本 `1.1.0`  
> 一句话结论：**功能完整、代码质量高于平均水平；工程化、交付安全、现场可诊断性是短板。建议先做“止血”，再做教学场景深化。**

---

## 1. 接手结论

这是一个已经能用的校园场景产品，不是原型：

- 前端 136 个 TS/TSX 文件、约 1.68 万行；类型严格（`strict` + `noUnused*`），lint 零告警。
- 生产构建约 0.8 秒；`dist` 与 U 盘 `网页版` **逐字节一致**，说明当前源码就是线上版本。
- exe 三处（`campus-exe/out`、`campus-exe/release`、U 盘根目录）**SHA256 完全一致**，发布链路没有“拿错包”。
- 功能覆盖聊天、深度思考、联网搜索、图片 OCR、相机、快捷卡片、文档分屏、表格提取、语音、历史导入导出，完成度较高。
- 代码注释质量好，`reply.ts`、`branches.ts`、`zipReader.ts`、`db.ts` 等核心逻辑对边界情况考虑充分。

但“能跑”不等于“能长期维护和放心分发”。目前最大的问题不在功能，而在：

1. **API Key 以明文进入 exe**，exe 发到哪，密钥就泄露到哪。
2. **校园版全部改动尚未提交**，一次误操作可能丢失数周工作。
3. **没有日志、没有错误边界、没有健康检查**，学校现场出问题只能靠猜。
4. **没有自动化测试和发布流水线**，每次发版靠手工步骤和记忆。

## 3. 风险清单

### P0：建议本周处理

#### P0-1 密钥随 exe 分发，且可被直接提取

**证据**

- `campus-exe/build.mjs` 读取 `campus-edition/config.json`（第 52–54 行），并在第 82 行把 `{ apiKey: '', ...config }` 嵌入 `server-template.cjs`。
- 对 `D:\校园助手\校园助手.exe` 做二进制字符串扫描，可以检索到 `apiKey`、`apiBase`、`sk-` 前缀；`apiKey` 与 `apiBase` 在文件中相邻出现，结构就是内嵌配置。
- 同一密钥还出现在：
  - `campus-edition/config.json`
  - `_backup/backup-usb-sync-20261120/campus-edition/config.json`
  - U 盘 `网页版/config.json`
- 交接文档只提醒“外借前移除 config.json”，但**没有提到 exe 本身也带 Key**。即使删掉 config.json，exe 里仍然有。

**影响**

- 任何拿到 exe 的人都能用 `strings` 一类工具提取密钥，消耗学校额度。
- 无法按设备吊销或限额；一把钥匙发给所有机器。
- 密钥已经存在于多个副本和备份中，应视为**已泄露**。

**建议动作（按顺序）**

1. **立即轮换密钥**，旧 Key 作废；清理所有备份中的明文 Key。
2. 构建默认**不嵌入**真实 Key：`build.mjs` 只有在显式设置 `CAMPUS_EMBED_KEY=1` 时才嵌入，否则生成不带 Key 的 exe，首次启动引导填写同目录 `config.json`。
3. 增加 `config.example.json`（只有 `apiBase` 和空 `apiKey`），并把真实 `config.json`、`config.local.json` 加入 `.gitignore`。
4. 多机场景优先改为**校内网关**：网关持有 Key，客户端只拿设备令牌；或者至少做到一机一 Key、可限额、可吊销。
5. 设置/关于页显示 Key 指纹（如后 4 位）和“当前使用哪个配置”，方便管理员核对，不显示完整 Key。

#### P0-2 校园版全部改动未提交

**证据**

- `campus-src` 的 `HEAD` 与 `origin/main` 都是 `429af5a chore: release v0.1.2`（上游提交）。
- `git status`：24 个已修改文件 + 31 个未跟踪条目（`src/components/campus/`、`src/services/campus/`、`src/assets/`、`campus.css`、`AppLogo.tsx` 等）。
- `campus-exe/`、`campus-edition/`、`docs/` 根本不在任何 Git 仓库里。

**影响**

- `git checkout .`、`git clean -fd`、磁盘故障、换电脑，都可能让校园版工作全部丢失。
- 没有提交历史，无法定位“哪个改动导致表格提取坏了”，也无法回滚。
- 打包脚本和文档没有版本，exe 与源码的对应关系只能靠人工记忆。

**建议动作**

1. 新建自己的私有仓库（或在父目录建 monorepo），把 `campus-src`、`campus-exe`、`campus-edition`、`docs` 纳入版本控制；保留 `upstream` 指向 `deepseek-ai/chat-demo`，**不要向 upstream 推送**。
2. 先提交一个“现状快照”，打 tag（如 `campus-v0.1.2`），再开始改。
3. `.gitignore` 至少排除：`node_modules/`、`dist/`、`campus-exe/out/`、`campus-exe/release/`、`config.json`、`*.exe`、`_backup/`、`_archive/`。
4. 每次发布 exe 时在 release note 里记录：版本号、commit、SHA256、构建日期。

#### P0-3 现场可诊断性不足

**证据**

- `build.mjs` 第 134–141 行把 exe 改成 GUI 子系统，双击不弹黑窗，但也意味着 `console.error` 全部看不见。
- 全项目没有 `ErrorBoundary`、`componentDidCatch` 或全局 `window.onerror`；React 渲染异常会直接白屏。
- 没有 `/health` 或类似接口；`server-template.cjs` 第 205–215 行遇到 `EADDRINUSE` 时，**不检查占用端口的是谁**，直接打开 `http://127.0.0.1:8130`。如果旧版本还在跑，用户看到的是旧界面；如果是别的软件占用，打开的是错误页面。
- 没有日志文件，学校现场无法提供“什么时候、哪个请求、报了什么错”。

**建议动作**

1. 增加 `GET /health`，返回 `{ app, version, pid, startedAt, configured, configSource }`；启动时先探测该端口：
   - 是同应用的旧实例 → 提示版本并打开，或直接退出让用户关旧实例；
   - 不是本应用 → 自动换端口（8131、8132…）或弹窗说明。
2. 服务端写滚动日志到 `%LOCALAPPDATA%\CampusAssistant\logs\`，记录启动、端口、配置来源、代理错误（**不记录 Key 和请求正文**）。
3. 前端加 `ErrorBoundary` + `window.onerror` / `unhandledrejection`，白屏时显示“重新加载 / 导出诊断信息”，而不是一片空白。
4. 设置里加“诊断”页：版本、端口、配置来源、最近错误、存储占用、导出诊断包。

#### P0-4 版本号三处不一致

**证据**

- `campus-src/package.json`：`0.1.2`
- `campus-exe/build.mjs` 第 116–127 行：文件/产品版本硬编码 `1.1.0.0` / `1.1.0`
- `campus-src/src/index.html`：图标缓存版本 `?v=6`，手工维护

**影响**

- 用户看 exe 属性是 1.1.0，应用内是 0.1.2，客服/交接时对不上。
- 图标版本靠手改，容易忘记，导致任务栏/favicon 不更新。

**建议动作**

- `build.mjs` 读取 `package.json` 的 `version`，写入 exe 资源；前端通过 `DefinePlugin` 注入 `__APP_VERSION__`，在“关于”里显示。
- 图标 URL 的 `?v=` 改为构建时注入的版本号或内容哈希。
- `/health` 返回同一个版本号。

### P1：两到四周内处理

#### P1-1 本地代理安全加固

- `campus-edition/serve.mjs` 第 143 行用 `target.startsWith(ROOT)` 判断目录边界。前缀比较不是严格的目录边界：如果存在同前缀的兄弟目录（如 `网页版2`），理论上可绕过。应改用 `path.relative(ROOT, target)`，拒绝以 `..` 开头或为绝对路径的结果。
- 代理没有校验 `Origin` / `Host`，也没有令牌。绑定 `127.0.0.1` 能挡住外网，但挡不住 DNS rebinding 和本机其他进程。建议：
  - 启动时生成随机令牌，写入 HttpOnly Cookie；代理请求校验令牌；
  - 校验 `Host` 必须是 `127.0.0.1:端口` / `localhost:端口`；
  - 校验 `Origin`（若存在）必须是同源；
  - 对代理接口做简单限流。
- `serve.mjs` 第 33–44 行把请求体整体读进内存，上限 120 MB；大文件上传时内存峰值高。可以改为流式转发（Node `fetch` 的 `duplex: 'half'`）。
- `server-template.cjs` 第 31–38 行读取同目录 `config.json` 时**没有去 BOM**；带 BOM 的文件会 `JSON.parse` 失败，然后静默回退到内嵌配置。用户以为覆盖了 Key，实际没有。应去 BOM，并在解析失败时明确报错，而不是静默回退。
- 静态响应建议加 `X-Content-Type-Options: nosniff`、`Referrer-Policy`、基础 CSP。
- 如果未来要支持局域网多机访问：`http://192.168.x.x` 不是安全上下文，`crypto.randomUUID`、剪贴板、摄像头、语音都会受限；必须上 HTTPS 反向代理。当前设计实际上只适合本机 `127.0.0.1`。

#### P1-2 测试与 CI 空白

- `package.json` 没有 `test` 脚本，仓库里没有测试文件。
- 现有 `.github/workflows/pages.yml` 是上游的 Pages 部署：一旦把校园版推到自己的 `main`，它会构建并发布静态站点。但校园版依赖本地代理，Pages 上没有代理，聊天接口不可用；同时会把校园 Logo/素材公开发布。建议删除该工作流，或改成只跑 type/lint/build 的 CI。
- 建议先测纯逻辑，不追求覆盖率数字：
  - `reply.ts`：事件合并、续写、拒绝、上下文裁剪；
  - `branches.ts`：编辑/重新生成/切换版本；
  - `history/zipReader.ts` + `schema.ts`：坏 ZIP、路径穿越、CRC、BOM；
  - `campus/tableExtract.ts`：标记解析、姓名列推断；
  - `api/sse.ts`：分片、CRLF、BOM、中止。
- E2E 可用 Playwright：启动 `serve.mjs` + mock API，覆盖“新建会话 → 发消息 → 流式回复 → 刷新后仍在”。

#### P1-3 数据、隐私与共享设备

- 会话和附件在浏览器 IndexedDB 里。同一 Windows 账户/Edge 配置文件下，所有使用者共享历史；教室一体机尤其明显。建议：
  - 增加本地“使用者/班级”配置，至少做到会话分组和启动时选择；
  - 或提供“退出时清除本机记录”模式（管理员开关）。
- 学生照片、作业、对话会发到 DeepSeek。首次启动应有隐私告知（发送哪些数据、保存在哪里、如何删除），设置里可回看。
- 远端 Files API 的文件**从不删除**（`store.ts` 中 `removeSession` 注释明确说明，因为导入/编辑/重新生成会复用同一附件，未做引用计数）。长期使用会累积配额。建议加“远端文件清理”：按本地引用计数找出无引用文件，调用 `DELETE /anthropic/v1/files/{id}`，并提供“只清远端、保留本地”的选项。
- 目前只有“导出全部 / 导入覆盖全部”，没有自动备份、没有合并导入、没有单会话导出。建议：
  - 每周提醒备份 / 一键导出；
  - 导入支持“合并”与“覆盖”两种；
  - 单会话导出 Markdown/PDF。
- 建议在设置里显示 IndexedDB 占用、附件数量、最近备份时间。

#### P1-4 双语不完整

- `CampusQuickPanel.tsx` 第 25–33 行：默认卡片标题、副标题、讲题提示词全是硬编码中文；切到 English 后仍然是中文。
- `TableExtractDialog.tsx` 第 199 行：`等 ${list.length} 处` 硬编码中文。
- `services/api/ocr.ts` 第 36 行、`server-template.cjs` 的 503 文案也是中文。
- 系统提示词 `SYSTEM_PROMPT` 是中文，且没有明确“用用户的语言回答”。
- 建议：内置卡片存 i18n key 而不是字面量；默认提示词按 locale 生成；系统提示词加一句“使用与用户相同的语言回答，除非用户明确要求其他语言”；服务端错误返回错误码，由前端翻译。

### P2：产品与工程深化

#### P2-1 教学场景：从“聊天工具”走向“课堂工作台”

当前功能不少，但还是以“会话”为中心，而不是以“一节课”为中心。建议围绕一条真实课堂工作流整合：

- **课前**：导入课件/学案 → 生成放映稿；从题库/课本生成随堂练习；准备快捷卡片。
- **课中**：展台拍照 → 讲题；表格标记 → 名单；全屏放映；语音输入/朗读。
- **课后**：导出板书/放映稿/名单；备份；分享给同组教师。

具体可做的增强：

- 表格提取：多页表格、Excel 原生样式（加粗/下划线/填充色）、任意图片消息上的“整理表格”入口、确认页可编辑（不只是勾选）、导出 CSV/Excel。
- 文档放映：打印/导出 PDF、演讲者视图（备注/下一页预览）、按屏幕比例适配。
- 相机：自动裁边、旋转、多拍连拍、文档/白板模式。
- 会话：本地全文搜索、置顶/归档、单会话导出。
- 用量：按天/月统计 token 与费用（`usage` 已经存在消息里，只差展示），管理员可设预算提醒。

#### P2-2 交付与运维

- **代码签名**：exe 未签名，学校环境容易触发 SmartScreen/杀软拦截。建议购买 OV/EV 证书，或至少在校内分发时提供哈希和说明。
- **Kiosk/自启**：当前是 `msedge --app=... --start-maximized`，不是真正 kiosk。若定位一体机，建议提供 `--kiosk` 模式、开机自启、管理员退出快捷键。
- **更新**：没有版本检查/自动更新。至少加“检查更新”（读取一个静态 manifest），避免每台机器手工拷 U 盘。
- **exe 体积**：61 MB 主要来自 Node 运行时。短期不必优化；长期可考虑用 Go/Rust 写一个更小的本地代理 + 静态文件服务，把体积降到 10 MB 级。
- **安装/卸载**：目前是绿色 exe。若进入学校统一采购，建议提供安装包、开始菜单快捷方式、卸载入口。

#### P2-3 代码与仓库清理

- 死代码：
  - `components/settings/ApiKeyField.tsx`
  - `components/settings/useApiKeyForm.ts`
  - `services/api/client.ts` 的 `verifyApiKey`
  - `services/settings.ts` 的 `setApiKey`
  - `ensureApiKey` 现在恒为 `true`（`apiKey` 固定 `'local-proxy'`），调用点可以删除或改成“检查本地服务是否已配置 Key”。
- `package.json` 的 `build` 脚本是 `rm -rf dist && NODE_ENV=production ...`，Windows 下不可用。建议用 `rimraf` + `cross-env`，或写一个 Node 脚本，让 `pnpm build` 在 Windows 也能跑。
- 加入 `knip`/`ts-prune` 之类的死代码检查；`oxlint` 已开启 `noUnusedLocals`，但只能发现文件内未使用，发现不了整文件死代码。
- 补 `THIRD_PARTY_NOTICES.md`：当前只复制了上游 MIT LICENSE，KaTeX、Mermaid、React 等第三方许可证没有汇总。
- Logo 授权：交接文档说明当前“大肥鱼”是网友同人二创、无明确授权。公开分发/商业采购前应替换为原创或取得授权，并在关于页注明来源。

## 5. 第一批建议立即开工的 5 件事

1. **轮换并移除内嵌 Key**（安全，最高优先级）。
2. **建立自己的 Git 仓库并提交当前快照**（防止丢失，成本最低）。
3. **加 `/health`、日志、ErrorBoundary**（现场可诊断）。
4. **版本号单一来源 + 一键发布脚本**（交付一致性）。
5. **Vitest 测试骨架 + CI**（后续所有改动的安全网）。

这 5 件事完成后，项目就从“能跑的交付物”变成“可以持续迭代的产品”。

## 6. 需要拍板的问题

1. **交付形态**：只做单机 U 盘/一体机，还是要支持校内局域网多机？
   - 单机：内嵌 Key 的风险可用“设备受控 + 不对外分发”接受，但仍建议默认不嵌入。
   - 多机：必须做网关/一机一 Key + HTTPS，否则密钥和隐私都不可控。
2. **数据合规**：学校是否允许把学生照片、作业、对话发送到 DeepSeek？需要怎样的告知/同意/留存策略？
3. **Logo**：继续用同人“大肥鱼”，还是换原创/已授权素材？
4. **优先方向**：先做工程化止血，还是先做表格/放映/相机等教学功能？
5. **是否现在就动手**：如果同意，我建议从第 1 周的 1–3 项开始。
